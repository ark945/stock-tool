# stock-tool 建置與自動化系統文件

本文件詳細說明 `stock-tool` 專案的系統架構、開發環境建置、數據管線執行以及 CI/CD 自動化部署流程。

---

## 1. 系統概覽 (System Overview)

`stock-tool` 採用混合式架構：
1. **前端 (Frontend)**：雙軌制
   - **傳統單頁模式 (Legacy SPA)**：基於根目錄下的 `index.html` 與 `smart-stock-source.html`，為無須編譯（No-Build）的純 HTML / CSS / JS 應用程式。
   - **現代化構建沙盒 (Vite Migration)**：位於 `vite-migration/` 目錄，採用 ES Modules 與 Vite 構建工具，逐步將單檔結構進行模組化拆分與重構。
2. **數據處理管線 (Data Pipeline)**：使用 Node.js (v18+) 與 Python 3 自動抓取、處理市場數據，並將結果輸出為 JSON 快取檔案存於 `data/` 目錄中。
3. **CI/CD 自動化**：利用 GitHub Actions 執行定時數據掃描、測試，並在代碼變更時自動部署至 GitHub Pages。

---

## 2. 環境要求 (Prerequisites)

在開始建置前，請確保您的開發環境已安裝以下工具：

- **Node.js**：v18.0.0 或更高版本
- **npm**：v9.0.0 或更高版本
- **Python**：v3.10 或更高版本
- **Ruby**（可選）：用於運行 `serve.rb` 本地伺服器（需安裝 WEBrick gem）
- **Git**：用於版本控制與 GitHub Actions 同步

## 3. 開發環境建置 (Development Setup)

### A. 運行傳統單頁應用 (Legacy Single Page)

傳統單頁應用無需任何構建步驟即可直接執行。為了避免瀏覽器跨來源資源共用 (CORS) 限制，建議透過本地靜態伺服器開啟：

#### 方式 1：使用專案內建 Ruby 伺服器
```bash
ruby serve.rb
# 預設啟動於 http://localhost:8000
```

#### 方式 2：使用 Python 靜態伺服器
```bash
python -m http.server 8000
# 瀏覽 http://localhost:8000
```

#### 方式 3：使用 VSCode Live Server 擴充套件
在 VSCode 中，右鍵點擊 `index.html` 並選擇 "Open with Live Server"。

您可以在專案根目錄下運行以下指令：

#### 1. 美股/台股相對強度龍頭掃描器 (RS Leader Scanner)

### D. 資料存放位置與讀取機制 (Data Storage & Reading Mechanism)

1. **資料存放路徑**：
   所有由數據管線腳本（Node.js / Python）抓取並處理後的結構化 JSON 資料，皆統一存放於專案根目錄下的 [`data/`](file:///D:/MyLab/stock-tool/data) 資料夾中。
2. **運行時數據讀取/寫入流程**：
   - **本地開發環境**：當您在本地手動執行 `node scripts/scan.js` 等腳本時，產出的 JSON 檔案會直接寫入並覆蓋本地的 `data/` 目錄。前端網頁 (`index.html` 或 Vite 開發伺服器) 會透過相對路徑直接請求（`fetch('./data/xxx.json')`）讀取最新數據。
   - **雲端與 GitHub Actions 環境**：當 GitHub Actions 工作流定時執行完成後，Actions 內部的 Git 機器人會將最新的 JSON 檔案 Commit 並 Push 提交回您的 GitHub Repository（此操作會使儲存庫中的 `data/` 目錄保持最新狀態），隨後透過 `pages.yml` 將最新檔案發布至 GitHub Pages 服務器上，確保線上用戶看到最新數據。
3. **本地端 (Local) 資料同步與更新方式**：
   - 當 GitHub Actions 於雲端定時抓取數據並推送回 GitHub 後，您本地的代碼庫將會落後（Behind）於遠端分支。
   - **如何同步本地資料**：您只需在本地專案目錄下執行以下指令，即可拉取最新的 JSON 數據檔案：
     ```bash
     git pull
     ```
   - **防衝突建議**：如果您在本地也手動運行過掃描腳本並產生了本地變更，在執行 `git pull` 前建議使用 `git checkout data/` 還原本地的快取變更，以確保順利拉取不發生 Git 衝突。
   - **程式在運行中如何更新資料？**：
     - **如果本地網頁伺服器（Ruby / Python / Vite）正在運行中**：您**不需要關閉伺服器**。可以直接在終端機執行 `git pull`。拉取成功後，只要在瀏覽器中「重新整理網頁 (F5 / Refresh)」即可直接讀取最新數據，伺服器會自動偵測並讀取磁碟上的新 JSON 檔。
     - **如果資料抓取腳本（Python/Node）正在跑**：請等待該抓取腳本執行完畢後，再執行 `git pull`，以避免讀寫檔案衝突或 Git 衝突。

## 6. CI/CD 自動化部署流程與設定 (GitHub Actions Configuration)

專案在 `.github/workflows/` 下配置了自動化工作流，確保數據定時更新與自動部署：

| 工作流檔案 | 觸發時機 / 頻率 | 功能說明 |
|---|---|---|
| `stock-scan.yml` | 每日開盤前/後 (Cron) | 執行 `scripts/scan.js` 更新 `us_scan.json` 與 `tw_scan.json` |
| `insider-scan.yml` | 每日美東時間傍晚 | 執行 `insider_scan.js` 向 SEC 抓取 Form 4 並更新 `insider_data.json` |
| `news-scan.yml` | 每 4 小時一次 | 抓取最新新聞並透過 FinBERT / Claude 進行情緒評估 |
| `pages.yml` | `main` 分支有代碼變更時 | 自動發布根目錄 `index.html` 與 `data/` 目錄至 GitHub Pages |
| `backtest.yml` | 每週定時 | 執行自動化策略回測並生成 `signal_stats.json` |
| `smoke-test.yml` | 每次 Pull Request / Commit | 執行代碼語法與腳本冒煙測試 (`smoke_test.py`) |

### GitHub Actions 設定步驟：

為了使 GitHub Actions 能夠順利抓取數據並自動提交更新回儲存庫，以及順利部署網頁，請至 **GitHub 專案頁面** 設定以下三大項目：

#### 1. 開啟儲存庫寫入權限 (Workflow Permissions)
因為定時抓檔腳本（如 `stock-scan.yml`）執行完畢後會使用 `git commit` 及 `git push` 將產出的 JSON 檔案提交回 `data/` 目錄，因此必須給予寫入權限：
1. 進入您的 GitHub Repository，點選右上角的 **Settings**。
2. 在左側選單中，展開 **Actions** 並點選 **General**。
3. 滑動至最下方找到 **Workflow permissions**：
   - 選擇 **"Read and write permissions"**。
   - 勾選 **"Allow GitHub Actions to create and approve pull requests"**。
4. 點選 **Save** 儲存設定。

#### 2. 設定 Repository Secrets (金鑰管理)
部分腳本會調用 Claude API 進行文字處理（如翻譯或敘事），需要設定金鑰：
1. 在 **Settings** 左側選單中，展開 **Secrets and variables** 並點選 **Actions**。
2. 點選 **New repository secret** 按鈕。
3. 設定金鑰資訊：
   - **Name**: `ANTHROPIC_API_KEY`
   - **Value**: 輸入您的 Claude API 金鑰（如 `sk-ant-xxx`）
4. 點選 **Add secret** 儲存。

#### 3. 設定 GitHub Pages 託管來源
此專案採用 `pages.yml` 直接利用 Actions 自動部署網頁，設定如下：
1. 在 **Settings** 左側選單中，點選 **Pages**。
2. 在 **Build and deployment** 區塊下：
   - **Source**: 選擇 **"GitHub Actions"**（此設定會讓 Pages 直接讀取 `pages.yml` 產出的 artifact，而不需要手動建立 `gh-pages` 分支）。
3. 當有任何程式碼推送到 `main` 分支，或定時腳本更新 JSON 後，Actions 就會自動將網頁部署上線，您可在頁面上方看到您的專案網址（格式通常為 `https://<您的帳號>.github.io/<專案名稱>/`）。

## 7. 環境變數與 Secret 設定

若需在本地執行包含 AI 分析與外部 API 的完整數據管線，請在環境變數或 `.env` 檔案中設定以下內容（在 GitHub Actions 中則設定於 Repository Secrets）：

### 💡 無 Claude API 金鑰的解決方案與影響說明：

如果您沒有 Claude API 金鑰，請不用擔心，專案的**核心功能完全不需要 AI 金鑰即可運作**。

#### 1. 受影響的非核心功能：
以下與 AI 相關的輔助功能將無法運作：
- `scripts/market_narrative.js`（每日大盤收盤 AI 敘事生成）
- `scripts/translate_summaries.js`（美股個股業務簡介的繁中翻譯）
- `scripts/ai_analysis.js` 與 `scripts/ai_diligence.js`（AI 個股診斷與盡調）

#### 2. 沒有金鑰時的系統表現：
- **GitHub Actions 自動化**：所有調用 AI 的步驟均配置了 `continue-on-error: true`。即使您沒有在 GitHub Secrets 中設定 `ANTHROPIC_API_KEY`，自動化管線在執行到 AI 步驟時只會報錯並自動跳過，**不會中斷整體執行**，核心的 `us_scan.json` 與 `tw_scan.json` 依然會順利產出。
- **前端網頁顯示**：網頁上的「今日大盤敘事」面板將會留空或顯示預設文字，美股個股的業務介紹會呈現原始英文（而非翻譯後的繁體中文）。

#### 3. 您的替代選擇：
- **選擇 A（直接忽略）**：不填寫 `ANTHROPIC_API_KEY`。此系統有 90% 的功能（動量掃描、相對強度排序、VCP 底型計算、三大法人買賣超）都是基於數學與統計模型，不需要 AI 金鑰即可完美運作。
- **選擇 B（修改為其他 API）**：如果您有其他 LLM 金鑰（例如 **Gemini API 金鑰**，其提供免費額度），您可以修改 `scripts/market_narrative.js` 與 `scripts/translate_summaries.js` 中調用 API 的 SDK，將其換成 Gemini API 或本地免費的 Ollama 服務。
